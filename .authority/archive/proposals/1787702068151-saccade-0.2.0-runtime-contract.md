# Saccade 0.2.0 runtime contract

Status: owner-directed proposal for the new Rust build.

This proposal supersedes the current execution-boundary fallback and defines
the next Runtime contract. Playwright is a source of lessons and an
out-of-band development oracle only; it is never linked into or invoked by the
product.

## Local actionability wait

- R-001 — One `saccade.act` request performs its actionability wait locally in
  the Extension; the Agent does not poll or sleep.
- R-002 — Before dispatch, the Extension requires the current document,
  runtime object, opaque token, visibility, enabled state, and current
  affordance.
- R-003 — Normal controls additionally require stable geometry and current
  topmost/focus evidence within a bounded timeout.
- R-004 — Object replacement is stale even when a semantic replacement looks
  equivalent; authority is never silently rebound.
- R-005 — Continuous `reflex_target` controls retain a separate bounded
  software execution policy and occurrence verifier.

## Strict object resolution

- R-006 — An `object_id` resolves to exactly one object in the current
  document.
- R-007 — A document, revision, or token mismatch fails closed before a side
  effect.
- R-008 — An ambiguous semantic query returns a bounded candidate set and
  never guesses.
- R-009 — Agent inputs never include CSS, XPath, DOM paths, locators, arbitrary
  JavaScript, or arbitrary coordinates.

## Web-first semantic waits

- R-010 — `truth.read` accepts `tab_id`, optional `after_revision`, a bounded
  semantic `query`, `min_objects`, and `timeout_ms`.
- R-011 — Broker waits locally for browser-pushed state and returns the first
  matching revision or a bounded failure; the Agent does not poll the page.
- R-012 — Fixed sleeps are not a protocol primitive or success criterion.

## One end-to-end deadline

- R-013 — Each MCP request creates exactly one monotonic deadline and passes
  its remaining budget through MCP → Broker → Extension → Collector.
- R-014 — No downstream layer restarts the full timeout.
- R-015 — Failures report `stage`, `code`, `elapsed_ms`, `retry_safe`, and the
  current revision when one exists.
- R-016 — A missing Extension fails immediately rather than consuming the
  action timeout.

## Cancellation and uncertain outcomes

- R-017 — Cancellation removes a command that has not been dispatched from
  the queue.
- R-018 — Once dispatched, cancellation is not reported as successful; the
  Runtime continues bounded occurrence reconciliation.
- R-019 — If reconciliation cannot determine the result, the receipt is
  `outcome_unknown` with `retry_safe=false`.
- R-020 — Actions are never automatically replayed after reconnection.

## Agent session and tab isolation

- R-021 — Each MCP connection owns a fresh opaque `agent_session_id`.
- R-022 — `tabs.open` leases the created tab to the calling session; one
  session may own multiple tabs, while one tab has at most one writer.
- R-023 — A session cannot read or act on another session's leased tab.
- R-024 — A user-shared tab is assigned explicitly to exactly one online Agent
  session.
- R-025 — When an Agent disappears, its leases become orphaned; tabs are not
  automatically closed, replayed, transferred, or exposed.

## Navigation lifecycle

- R-026 — With a connected Chrome or Edge Extension, `tabs.open` creates and
  authorizes a tab directly.
- R-027 — If the browser is not running, Saccade launches the user's normal
  Chrome or Edge and waits within the request deadline for the Extension.
- R-028 — Saccade never launches a bundled/test browser or creates a hidden or
  temporary profile.
- R-029 — `tabs.open` returns `tab_id`, `document_id`, initial revision, and
  readiness.
- R-030 — Navigation creates a new `document_id` and immediately invalidates
  every authority from the prior document.
- R-031 — Popups, new windows, and opener tabs do not inherit authorization.

## Bounded form batches

- R-032 — `saccade.act` may carry a bounded, preplanned batch of independent
  form operations.
- R-033 — The entire batch is resolved and preflighted before the first side
  effect; any initial ambiguity or invalidity rejects the whole batch.
- R-034 — Each executed step returns value-free semantic verification; the
  batch returns the final revision, `next_basis_revision`, and a compact
  transition.
- R-035 — Submit, navigation, upload, protected fill, and dependent or
  side-effect-ambiguous steps cannot be hidden inside an ordinary form batch.

## Action receipts

- R-036 — Every action receipt includes `command_id`, one of
  `accepted`/`rejected`/`outcome_unknown`, occurrence state, semantic
  postcondition, `document_id`, final revision, compact relevant delta,
  `retry_safe`, and `external_execution_required`.
- R-037 — A verified action result is self-sufficient; the Agent is not
  required to call `truth.read` again to prove the same postcondition.
- R-038 — `external_execution_required` is an explicit handoff, not permission
  for Saccade to invoke Playwright, CDP, page evaluation, or coordinate input.

## Useful first read

- R-039 — Broker stores one canonical current Truth for every authorized tab.
- R-040 — When the Agent supplies a known goal, the first read prefers a
  bounded semantic working set.
- R-041 — Small pages return a bounded full view; large pages return a complete
  compact catalog automatically; later reads return deltas.
- R-042 — The Agent does not select transport-shaped full/index/region modes.

## Secret-free diagnostics

- R-043 — Runtime keeps a bounded ring buffer containing command identity,
  tab/session/document/revision, stage timestamps, message sizes,
  reset/reconnect reason, failure code, and occurrence status.
- R-044 — Diagnostics never record passwords, protected or editable values,
  cookies, storage, full DOM, screenshots, tokens, credentials, file contents,
  or secret-bearing request payloads.
- R-045 — `doctor` returns only bounded summaries and recent machine-readable
  failure reasons.

## Cross-browser conformance

- R-046 — A release candidate is publishable only after the same Extension
  candidate passes Chrome and Edge conformance for first full observation,
  continuous delta, reconnect/full reset, tab open/close, form batch,
  replacement stale, continuous moving target, MCP restart, and multiple Agent
  sessions.

## Explicit non-inheritance from Playwright

- R-047 — Production never uses CDP, Playwright, bundled/test browsers, hidden
  browser profiles, exposed selectors/locators, `page.evaluate`, screenshots
  as Truth, arbitrary coordinates, ambiguous-side-effect retries, or
  Playwright as fallback.
- R-048 — The production implementation is the Rust Runtime plus the shared
  Chrome/Edge Extension on the single approved route.

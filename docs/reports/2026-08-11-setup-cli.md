# Setup CLI implementation report

Date: 2026-08-11

## Result

`packages/setup` now contains the dependency-free `@saccade/setup` CLI. It
implements install, doctor, update, uninstall, and explicit purge for the
first macOS release target.

Setup verifies the Runtime SHA-256 digest before writing files. It uses atomic
file replacement and restores prior files after a failed transaction. Updates
preserve the Profile. Ordinary uninstall preserves the Profile and refuses to
remove managed files that the user changed after setup.

The CLI installs user-level Chrome and Edge Native Messaging manifests. It
adds the STDIO MCP to Codex, Claude Code, and Claude Desktop when it finds those
clients. Existing entries with the same name remain untouched when their
configuration differs.

The Runtime now accepts a valid Chromium Extension origin supplied by Native
Messaging. The fixed development origin continues to use the separate Saccade
Dev directory. Development Extension builds select
`com.nanlogic.saccade.dev`; release builds select `com.nanlogic.saccade`.

## Publication blockers

The public npm registry has no package at `@saccade/setup`. The machine has no
authenticated npm session, so it cannot confirm ownership of the `@saccade`
scope or publish the package.

The macOS keychain has no valid code-signing identity. The package's bundled
`release.json` therefore remains `published: false` with no artifacts or store
Extension origins. Setup fails before writing files while that placeholder is
present.

# Saccade 0.2.2

Saccade 0.2.2 pairs the Node Broker with Extension 0.4.1 to fix a runtime
liveness failure found during a real browser workflow.

The Extension popup now reports the Broker connection field it actually
receives. A shared tab is `Ready` only when both semantic observation and the
local runtime connection are ready. Opening the popup also restores a missing
Broker command loop instead of leaving an authorized tab disconnected.

The underlying defect was a split bootstrap. The Extension opened its
keepalive before restoring authorized tabs, but it started its command consumer
only after every tab and Collector had recovered. One unresponsive Collector
could therefore leave a healthy WebSocket with no command poll. A keepalive
close during that same `connectPromise` could also lose the reconnect request.

The command consumer now starts before isolated background tab recovery.
Broker and Collector requests are bounded, a missing post-dispatch Collector
reply becomes `outcome_unknown` and is never retry-safe, and reconnect intent
survives an in-progress connection attempt.

The Broker no longer treats handshake metadata as command authority. It
requires a real command poll, identifies `consumer_not_started` and
`consumer_stale` connections in bounded doctor output, and withdraws work
queued during a poll transition if the consumer does not return. Pre-dispatch
withdrawal returns `EXTENSION_OFFLINE` with `retry_safe:true` instead of waiting
for the full request deadline. A closed keepalive marks the connection offline.

This patch preserves the six MCP tools, `saccade.node-broker/1`,
`saccade.observation/1`, exact tab leases, and the rule that an ambiguous side
effect is never replayed.

Install or update:

```sh
npx -y @nanlogic/saccade update
```

Release pair:

- npm: `@nanlogic/saccade@0.2.2`
- Extension: `0.4.1`
